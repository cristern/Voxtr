Activity Completion & Review Flow package -- documentation record.

ESTABLISHED DECISIONS PRESERVED (not reconsidered, only confirmed by investigation):
- TrainingService.logActivity's duplicate-PlannedActivity-logging
  prevention (S3.2, checked before any insert) is the correct
  application/domain boundary and was NOT rewritten -- only surfaced
  correctly in the UI, which previously didn't reflect it.
- There is one canonical logging service/persistence path
  (TrainingService.logActivity), reached from two legitimate entry
  points (ActivityDetailView's planned-activity flow via
  LogActivityView, and Daily Training's own unplanned-activity form).
  This is intentional multiplicity, not a duplicate implementation --
  both converge on the same service and the same duplicate-prevention
  check.
- LogActivityView already correctly dismissed only on confirmed save
  success and preserved entered values + error state on failure --
  unchanged.

NEW FINDINGS / IMPLEMENTATION THIS PACKAGE:
- Root cause of "unclear post-logging state": Activity Detail's own
  "Log Activity" button remained visible and tappable even after the
  activity was already logged -- the only feedback was a small status
  label. Fixed by replacing the button with a non-actionable "Logged"
  indicator once completed, and auto-dismissing Activity Detail back
  to wherever the user came from immediately after a successful log
  (via an isCompleted state transition, never firing on simply
  viewing an already-completed activity).
- This auto-dismiss naturally re-triggers the parent screen's own
  .onAppear (e.g. Daily Training's), which already refreshes Today's
  Logged Activities from canonical persisted data -- no new refresh
  mechanism was needed.
- PlannedActivityCompletion now optionally carries the actual
  LoggedActivity it was derived from (previously fetched via the
  existing PlannedActivityId relationship lookup, then discarded).
  Added as a defaulted, additive field -- no existing caller broke.
- Weekly Review's Planned Activities section now shows actual
  duration/RPE inline for completed items, using this same
  relationship -- never inferred from matching title/date (explicitly
  tested with two same-titled planned activities where only one was
  logged).
- Weekly Review's separate "Logged Activities" list was kept, not
  removed -- it can include unplanned/spontaneous logs with no
  PlannedActivity link at all, which is genuinely different
  information from the now-inline planned/actual pairing.

OUT OF SCOPE / UNCHANGED:
- Daily Focus remains a retained, deferred product concept.
- Recurring Location, address lookup, and all previously-listed
  backlog items untouched.
